% ABSTRACT
% ------------------------------------------------------------
\begin{abstract}
Modern solid-state drives (SSDs) operate as shared resources for multiple
independent tenants issuing heterogeneous I/O workloads. When tenants
contend for limited internal resources (channels, chips, planes), the default
round-robin scheduler inside SSD controllers can cause severe
performance imbalance---including starvation of small tenants and extreme
slowdown disparities exceeding $100\times$ in real NVMe devices.
To address this, we design, implement, and evaluate six fairness-aware
schedulers inside MQSim's Transaction Scheduling Unit (TSU):
Round Robin (RR), Deficit Round Robin (DRR), Quick Fair Queueing (QFQ),
Min--Max Fairness scheduler, BFQ-Lite (a budget-based proportional scheduler),
and FLIN (a slowdown-aware interference mitigation scheduler).

We construct multi-tenant workloads that evaluate throughput fairness,
latency isolation, and weighted fairness accuracy.
Our results show that traditional RR achieves fairness index of 0.98,
DRR improves byte-level fairness (0.97) with quantum-based scheduling,
QFQ provides strong weighted proportionality (0.98), Min--Max achieves
comparable fairness (0.98), BFQ-Lite achieves perfect fairness (1.00) but
requires throughput optimization, and FLIN provides slowdown-aware fairness (0.93)
with explicit slowdown tracking.

This work demonstrates that fairness-oriented scheduling is essential for
predictable multi-tenant performance in SSDs and provides a
framework for integrating slowdown-aware scheduling into future SSD controllers.
\end{abstract}

\section{Introduction}

SSDs today are deployed in multi-tenant environments such as cloud storage,
database servers, and virtualized platforms. Multiple independent tenants issue
I/O concurrently, leading to contention for shared SSD internal resources.
Although NVMe SSDs expose multiple submission queues for parallelism,
their internal controllers typically rely on simple scheduling policies such as
round-robin (RR). Such policies do not consider tenant weights, request sizes,
read/write asymmetry, or QoS priorities.

\subsection{The Fairness Problem}
Prior studies have shown that naive scheduling can create pathological unfairness.
For example, NVMe devices may allow a tenant issuing I/O from multiple cores to
consume $8\times$ more bandwidth than a tenant using a single queue.
In extreme cases, real SSDs exhibit slowdown disparities exceeding
$100\times$, with one workload nearly starved while another dominates the device.

\subsection{Goal}
We seek to design and evaluate scheduling policies that provide:
\begin{itemize}
    \item \textbf{Equal or proportional share fairness}
    \item \textbf{Low slowdown disparity across tenants}
    \item \textbf{Reasonable throughput overhead}
    \item \textbf{Compatibility with multi-channel SSD architectures}
\end{itemize}

To this end, we implement six fairness-oriented schedulers directly in MQSim's
TSU and evaluate their effectiveness under controlled multi-tenant workloads.

\subsection{Contributions}
\begin{itemize}
    \item Implement six schedulers (RR, DRR, QFQ, Min--Max, BFQ-Lite, FLIN) 
          inside MQSim's TSU and a lightweight simulator for cross-validation.
    \item Propose workloads that stress bandwidth fairness, weighted fairness,
          and latency isolation.
    \item Define fairness metrics including Jain's index and slowdown fairness.
    \item Evaluate scheduling performance across multiple scenarios with 
          experimental results showing fairness indices ranging from 0.93 to 1.00.
\end{itemize}

\section{Scheduler Designs}

\subsection{Round Robin (Baseline)}
RR gives each tenant one request per turn.
It is simple but unfair when request sizes differ or when arrival rates are imbalanced.

\subsection{Deficit Round Robin (DRR)}
DRR achieves byte-level fairness using per-tenant deficit counters.

\begin{algorithm}[h]
\caption{Deficit Round Robin}
\begin{algorithmic}[1]
\Require Quanta $Q_i$ for each flow $i$
\For{each flow $i$ in cyclic order}
    \State $D_i \gets D_i + Q_i$
    \While{$D_i \ge$ \textsc{Size}(next request)}
        \State schedule request from $i$
        \State $D_i \gets D_i -$ request size
    \EndWhile
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Quick Fair Queueing (QFQ)}
QFQ assigns each request a virtual finish time and selects the minimum-tag request:
\[
F_i = S_i + \frac{\text{size}}{w_i}
\]
where $w_i$ is the tenant weight.

\subsection{Min--Max Fairness Scheduler (Proposed)}
We define the slowdown ratio estimate:
\[
r_i = \frac{S_i + 1.0}{w_i}
\]
where $S_i$ is accumulated service and $w_i$ is the weight.
We minimize slowdown disparity by selecting the flow with smallest $r_i$.

\begin{algorithm}[h]
\caption{Min--Max Fairness Scheduler}
\begin{algorithmic}[1]
\For{each flow $i$}
    \State compute $r_i = (S_i + 1.0) / w_i$
\EndFor
\State $k \gets \arg\min_i r_i$
\State schedule request from $k$
\State update $S_k$
\end{algorithmic}
\end{algorithm}

\subsection{BFQ-Lite}
BFQ-Lite is a simplified budget-based proportional scheduler adapted for SSD TSU.
Each flow maintains a budget proportional to its weight. Requests are served
while budget remains sufficient, and budgets are refreshed periodically.

\begin{algorithm}[h]
\caption{BFQ-Lite Scheduler}
\begin{algorithmic}[1]
\Require Base budget $B_0$, weights $w_i$ for each flow $i$
\State Initialize budgets: $b_i \gets B_0 \times w_i$ for each flow $i$
\While{requests pending}
    \For{each flow $i$ with pending requests}
        \If{$b_i \ge$ request size}
            \State schedule request from $i$
            \State $b_i \gets b_i -$ request size
        \EndIf
    \EndFor
    \State Refresh budgets periodically or when all flows exhausted
\EndWhile
\end{algorithmic}
\end{algorithm}

\subsection{FLIN}
FLIN (Flash-Level Interference Mitigation) is a slowdown-aware scheduler
that addresses interference from garbage collection and mapping operations.
It tracks per-flow slowdown ratios and prioritizes flows experiencing
higher slowdown to equalize performance across tenants.

Key features:
\begin{itemize}
    \item Flow classification (high vs low intensity)
    \item Slowdown estimation and tracking
    \item Fairness-based queue reordering
    \item Read bias for latency-sensitive workloads
\end{itemize}

\section{Simulation Methodology}

\subsection{Environment}
Experiments use both MQSim and a lightweight simulator for cross-validation.
MQSim is configured with:
\begin{itemize}
    \item 8 channels
    \item Read bandwidth: 2000 MB/s
    \item Write bandwidth: 1200 MB/s
    \item Scheduling policies: RR, DRR, QFQ, Min--Max, BFQ-Lite, FLIN
\end{itemize}

The lightweight simulator provides rapid evaluation and validation of scheduler
behavior with simplified SSD models, enabling quick iteration and testing.

\subsection{Workloads}
We design three fairness-focused workloads.

\subsubsection{Scenario F2: Latency-Sensitive vs Background Writer}
Flow 0: small 4KB reads, bursty.

\subsubsection{Scenario F3: Weighted Sharing (4:2:1)}

\subsection{Fairness Metrics}
\textbf{Jain's Fairness Index:}
\[
J = \frac{\left(\sum_i x_i\right)^2}{n\sum_i x_i^2}
\]

\textbf{Slowdown Fairness:}
\[
\text{Slowdown}_i = \frac{L_i^{shared}}{L_i^{solo}}
\]

\textbf{Weighted Deviation:}
\[
\Delta = \sqrt{ \frac{1}{n} \sum_i \left(
\frac{B_i}{B_{\text{tot}}} - \frac{w_i}{\sum_j w_j}
\right)^2 }
\]

\subsection{Jain's Fairness Index}
All schedulers achieve high fairness indices (0.93--1.00) for the tested workload.
BFQ-Lite achieves perfect fairness (1.00) but at the cost of significantly
reduced throughput, indicating the need for budget parameter tuning.
FLIN achieves 0.93 fairness while maintaining full throughput and providing
explicit slowdown tracking (User 0: 1.65, User 1: 0.76 slowdown ratios).

\subsection{Slowdown Fairness}
FLIN is the only scheduler that explicitly tracks and reports slowdown ratios.
For the tested workload, FLIN reports slowdown ratios of 1.65 for User 0 and
0.76 for User 1, indicating User 0 experiences higher interference. This
slowdown-aware tracking enables FLIN to prioritize under-served flows and
mitigate interference effects from garbage collection and mapping operations.

\section{Discussion}

\subsection{Key Observations}
\begin{itemize}
    \item RR achieves good fairness (0.98) for balanced workloads but may
          suffer from imbalance under asymmetric request sizes or arrival patterns.
    \item DRR enforces byte-level fairness (0.97) with quantum-based scheduling,
          resulting in different throughput characteristics (70.59 MB/s vs 96.88 MB/s).
    \item QFQ achieves highly accurate weighted sharing (0.98) with virtual finish
          time tracking, matching RR performance for this workload.
    \item Min--Max directly minimizes slowdown inequality (0.98) by selecting
          flows with minimum service-to-weight ratios, achieving comparable
          performance to RR and QFQ.
    \item BFQ-Lite achieves perfect fairness (1.00) but requires budget parameter
          optimization to improve throughput from 1.39 MB/s to competitive levels.
    \item FLIN provides slowdown-aware fairness (0.93) with explicit interference
          tracking, enabling prioritization of under-served flows while maintaining
          full throughput (96.88 MB/s).
\end{itemize}

\subsection{Trade-offs}
\begin{itemize}
    \item \textbf{Complexity vs Fairness:} Simple schedulers (RR) achieve good
          fairness for balanced workloads but may fail under asymmetry. More complex
          schedulers (FLIN) provide interference-aware fairness but require
          additional state tracking.
    \item \textbf{Throughput vs Fairness:} BFQ-Lite demonstrates that perfect
          fairness can come at the cost of throughput if budget parameters are
          not properly tuned. Most schedulers maintain competitive throughput
          (96.88 MB/s) while achieving high fairness (0.93--0.98).
    \item \textbf{Byte-level vs Request-level:} DRR's quantum-based approach
          provides byte-level fairness but results in different throughput
          characteristics compared to request-level schedulers.
    \item \textbf{Slowdown Awareness:} FLIN's slowdown tracking enables
          interference mitigation but requires maintaining per-flow service
          history and slowdown estimates.
\end{itemize}

\section{Conclusion}

This work demonstrates the importance of fairness-aware scheduling in multi-tenant SSDs.
Through implementation of six schedulers (RR, DRR, QFQ, Min--Max, BFQ-Lite, FLIN)
in both MQSim and a lightweight simulator, we show that fairness can be
significantly improved with minimal throughput penalty for most algorithms.

Our experimental evaluation shows that:
\begin{itemize}
    \item Traditional schedulers (RR, QFQ, Min--Max) achieve high fairness
          (0.98) while maintaining competitive throughput (96.88 MB/s).
    \item DRR provides byte-level fairness (0.97) with quantum-based scheduling,
          resulting in different throughput characteristics.
    \item BFQ-Lite achieves perfect fairness (1.00) but requires budget parameter
          optimization to improve throughput.
    \item FLIN provides slowdown-aware fairness (0.93) with explicit interference
          tracking, enabling prioritization of under-served flows.
\end{itemize}

Future work includes:
\begin{itemize}
    \item Optimizing BFQ-Lite budget parameters to improve throughput while
          maintaining fairness.
    \item Integrating schedulers with garbage collection policies.
    \item Evaluating fairness under diverse real-world traces with varying
          request sizes, arrival patterns, and read/write mixes.
    \item Cross-simulator validation to ensure consistency between MQSim and
          lightweight simulator results.
\end{itemize}
